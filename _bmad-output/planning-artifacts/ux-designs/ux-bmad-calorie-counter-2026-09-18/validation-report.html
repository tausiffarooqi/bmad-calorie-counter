Calorie Tracker MVP — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-bmad-calorie-counter-2026-09-18/

A well-inherited, consistently-applied spine pair — the brand model (calm/editorial, clay + sage, no shadows) and the behavior model (single-user, tap-first, plural recommendations per slot) both read as decided rather than drifted, and every FR/AD cross-reference checked resolves to something real. The misses clustered in two mechanical spots rather than being spread thin: four behaviorally-specified components had no DESIGN.md visual row, and both spines cited a mockups/ path that didn't exist yet.

All 9 findings below (2 high, 5 medium, 2 low) were fixed in this session immediately after this review ran — the chosen mockup was promoted from .working/ to mockups/daily-view.html and both stale citations corrected, DESIGN.md gained visual rows for the four orphaned components, the recommendation typography token gained its missing fontStyle, contrast ratios were measured and documented, button-component inheritance was made explicit, and EXPERIENCE.md gained the missing cold-load / hard-failure / Preferences / Trends state rows plus UJ citations on every Key Flow. This report reflects the review as originally run, before those fixes.

1. Flow coverage

Strong

All 4 PRD journeys (first-login/breakfast, photo-logged lunch, text-logged snack, over-target evening) have a corresponding Key Flow with a named protagonist (Tausif), numbered steps, an explicit Climax beat, and a failure path or a reasoned statement that none applies.

No findings.

2. Token completeness

Adequate

Every color token is hex-valued and every {path.to.token} reference in both files resolves to a real frontmatter key — no broken token refs found.

MediumFixed

Recommendation typography token has no machine-readable italic flag

DESIGN.md Typography; EXPERIENCE.md Component Patterns
A consumer extracting the YAML alone gets upright Lora, missing the one visual trait the prose repeatedly calls the role's defining signature.
Fix: Added a fontStyle: italic key to the recommendation token.
LowFixed

No stated contrast ratio for primary-on-card

DESIGN.md Colors; EXPERIENCE.md State Patterns "Over-Target"
The clay-on-card pairing carries the Over-Target banner's message — a legibility-load-bearing case for the "calm, not alarming" intent. No formal WCAG level was targeted (a deliberate, logged decision), so this wasn't a violation, but it was unchecked.
Fix: Measured and documented: primary-on-card 4.48:1, foreground-on-background 10.28:1, muted-foreground-on-card 3.45:1, with usage guidance for each.

3. Component coverage

Thin

DESIGN.md.Components and EXPERIENCE.md.Component Patterns agreed on only 3 of 7 named components (Entries list, Recommendation card, Over-Target banner) with real visual + behavioral rules on both sides.

HighFixed

Four components had no DESIGN.md visual row

DESIGN.md.Components
In-progress indicator, Retry prompt, Photo-only notice, and First-login prompt cards each had an EXPERIENCE.md behavioral row but nothing on the visual side. The muted-earth mockup already contained a working .prompt-card treatment that answered two of these directly.
Fix: Added all four rows to DESIGN.md, lifting the prompt-card treatment from the mockup rather than inventing fresh.
MediumFixed

Button naming mismatch between spines

DESIGN.md.Components; EXPERIENCE.md Component Patterns
DESIGN.md names the generic components "Button (primary)"/"Button (secondary)"; EXPERIENCE.md's table names the same controls "Log buttons (Add Photo / Add Text)" and never states the inheritance.
Fix: Added one sentence to EXPERIENCE.md's Component Patterns intro stating every button on every surface is one of DESIGN.md's two Button components.

4. State coverage

Adequate

The states that carry the product's real differentiation — 2-slot vs. 1-slot vs. after-10pm vs. Over-Target on the Daily view, and the three First-login variants — were covered in real depth, each with a concrete treatment.

MediumFixed

No cold-load/skeleton state for the Daily view

EXPERIENCE.md State Patterns
Both example spines this rubric checks against cover an equivalent row; ours had none.
Fix: Added a Cold load row.
MediumFixed

No hard-failure state for the estimation call itself erroring

EXPERIENCE.md State Patterns / Component Patterns
The only failure state was FR-4's insufficient-detail retry; a network drop or the Gemini call erroring outright (a real external dependency per ARCHITECTURE-SPINE.md AD-2) had no defined treatment.
Fix: Added a distinct Hard estimation failure row, reusing the retry-prompt visual treatment with different copy.
LowFixed

No State Patterns rows for Account/Preferences or Historical Trends

EXPERIENCE.md State Patterns
No save-confirmation or validation-error state for Preferences; no loading or "no data at all yet" state for Trends.
Fix: Added Preferences saved, Preferences validation error, and Trends no-Entries-at-all rows.
